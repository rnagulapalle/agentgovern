# Generic control workspace — first increment

This candidate organizes the installed control plane by jobs: Overview, Workflows,
Runs, Approvals, Agents, Connections, Policies & access, Output controls,
Reconciliation, and History. Pricing and customer handoffs are sample resources
inside those jobs. No customer, prospect, or demonstration script defines the
workspace hierarchy.

The bounded control installation now opens an authenticated overview instead of
redirecting to quotes. Its additional page entries are presentation-only GET/HEAD
views behind the unchanged invited-member layout. They consume only the existing
pricing and connector GET contracts. No API method, identity, policy decision,
approval, lease, dispatch, or reconciliation authority is added. The quote-only
profile retains its original redirect and restricted route set. Unknown profiles
and unknown/malformed protected routes remain denied.

Approvals and unresolved effects link to the immutable request in its original
action workspace using a URL fragment. Full identifiers are secondary details;
labels describe the proposed business operation. Refresh performs read requests
only. Independent source failures preserve explicit partial coverage, never a
zero-work claim. Quote-plan decisions are explicitly separate from this queue.

Connections distinguishes agent platforms, sample business systems, and model
planning. Policy availability is not a provider-health check. AWS, Microsoft and
Google remain not connected in this deployment. Existing discovery source is not
enabled by this presentation increment. General output filtering and data-loss
controls are explicitly uninstalled; provider-twin message acceptance does not
establish them. No generated template or simulated output is presented as live
enterprise enforcement.

Measured checks: rendered navigation/profile restrictions; mounted Chromium with
labelled API response doubles for exact links, GET-only refresh, partial403,
malformed/unknown states and connection-scope labels. These tests do not establish
real cloud onboarding, native provider effects, independent user acceptance, or a
production deployment. Full quality and release checks remain separate receipts.

Next increments: readable run/agent detail views; supported cloud onboarding and
owner mapping; observed activity; installed controlled path and bypass proof;
scoped output enforcement where a supported contract exists; independent operator
navigation and recovery evaluation. Reuse current durable controls and discovery
contracts rather than constructing a parallel execution engine.

The action overview is a recent slice: each installed snapshot returns at most 100 actions. Empty lists describe only loaded rows, never the absence of older pending work.

## Invited administrator product view

The saved control workspace labels invited human accounts **Workspace administrator**. This is a presentation persona, not a new authorization role. Existing server authority remains `operator`, obtained only from the active tenant-scoped member directory and authenticated session. Scoped workload keys never receive this persona or human authority.

Policies & access enumerates supported registration, boundary configuration, exact review, execution, verification, containment, and history inspection. It also states that administrator visibility cannot bypass self-approval restrictions, hard limits, tenant scope, or unsupported actions. Invitations, cloud IAM administration, and billing are not implemented by this persona.

Policies & access and Connections include a full product capability catalog. The current isolated control profile exposes bounded quote planning; arbitrary chat workflow generation, inbox monitoring, cloud discovery/import, and general output enforcement remain unavailable. Unavailable capabilities do not link to blocked routes. All installed action controls retain their original server checks.

Validation of this increment must distinguish read-only presentation tests from actual production founder membership and independent approval checks. No credentials are altered by the increment.

The shared connector snapshot may include quote updates and quote confirmation email (`quote-step-1`). The customer action queue validates all known connector discriminators, then excludes quote updates and quote-contract email. Quote policy rows are validated but not treated as customer policy. Counts describe customer actions within the latest 100 connector actions, not 100 customer-only records. Unknown connector/state data remains unconfirmed.
