# Exact connector request snapshots

The bounded acknowledgement now saves an exact `prepared-request-1` snapshot:
method, provider resource, atomic source condition and complete request body. The
message snapshot includes sender, recipient, subject and text. No credential or
authorization header is stored. Connector destination remains separately bound.

Snapshots are generated by the server and included in the existing action approval
hash. Public proposals cannot supply them. Saved plans also freeze both request
snapshots inside their plan hash. Creating a run or submitting a step compares the
request against that reviewed plan; reviewing a plan never grants execution approval.
Migration 11 protects persisted proposal fields from UPDATE/DELETE. No migration
rewrites older plans/actions or grants missing authority.

Both adapters check the exact request contract before writing or reading effects.
They send the saved method, resource and body, with stable action-ID idempotency and the saved CRM version
condition. The controller rechecks at independent approval, dispatch and verification.
A mismatch prevents dispatch or preserves uncertainty after a possible effect; no
blind resend. A downstream step additionally requires each predecessor to match the
current destination and request contract, alongside existing state, policy and
identity checks. Success at an old destination cannot release a new destination.

The workspace shows the saved request for submitted work. It never substitutes
current template text for missing historical content. Missing/unsupported historical
requests are unavailable for display and cannot establish new execution authority.
Unsubmitted standalone step previews remain proposals, not approved evidence.

## Version and rollout boundary

`lib/connectors/content.ts` retains the v1 acknowledgement representation. A content
change requires a new reviewed contract/version and compatibility proof. Editing the
v1 implementation in place makes an old saved request fail comparison; it must not
silently change what is sent. Temporal history pins run representation, never current
permission. The current wire contract remains one lifecycle update and one sample
acknowledgement; this does not add arbitrary text, recipients or workflow graphs.

Older plans/actions without request snapshots stay readable as history but cannot
start new work under this contract. Prepare fresh reviewed work and independent
approvals after checking prior provider effects; never use new IDs to duplicate an
already completed business operation. Production cutover still requires a reviewed
pending-run policy. This phase is not deployed, does not switch dispatcher ownership,
and does not establish hosted CRM atomic source-version enforcement or real delivery.

## Verification

Dedicated PostgreSQL/controller tests cover exact stored requests, client injection,
same-ID replay, database rewrite refusal, legacy-plan refusal and predecessor binding
changes. Adapter tests reject altered method/resource/version/body before HTTP. The
actual connector proof additionally uses a saved independent approval, tests adapter
and database refusal, preserves provider effects on the rejected attempt, and checks
that the one actual twin write equals the original saved request body.

All affected actual HTTP, hosted, Temporal, archive restore, secure-container and
real-model/browser proofs must be rerun against frozen source and freshly built
application/worker artifacts. These are local prototype proofs, not enterprise
production acceptance, multi-record capacity or independent certificates.

Measured on frozen source: 29 connector checks, 7 hosted checks, 7 Temporal
crash/replay checks, 7 version checks, 6 dispatch checks, 10 packaged-service
checks, 17 fresh secure-container checks, 4 real application archive checks and
12 real-model/browser checks passed. All nine records include request/content
source fingerprints and were checked against the final source. Full quality
passed, including coverage, worker bundles, 75 routes and 52 rendered destinations.
The newly built `looplabs-temporal:request-proof` image was used for the container
drill. Production remains unchanged.
